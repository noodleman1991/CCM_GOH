Part one

The nine things only you can do

Each one is written the same way: what breaks while it's undone, the exact steps, and a command that proves it worked. Tasks 1–8 are independent — do them in any order. Task 9 is a sequence where order matters.

Vercel environment

Project connecting-climate-minds · Settings → Environment Variables
01

Set CRON_SECRET

You Blocks 3 jobs

Until this is set, all three scheduled jobs return 401 and never run: the weekly digest, event reminders, and the GDPR retention purge. They fail closed deliberately — an unset secret must not leave a mail-sending or data-deleting endpoint publicly triggerable. The privacy policy promises retention that nothing is currently enforcing.

  1. Generate a secret locally (below).
  2. In Vercel → Settings → Environment Variables, add CRON_SECRET to Production (add it to Preview too if you want to test there).
  3. Redeploy. Vercel sends the value as Authorization: Bearer … to every path listed under crons in vercel.json.
# generate
openssl rand -base64 32
Verify With the header you should get 200; without it, 401. 
curl -s -o /dev/null -w '%{http_code}\n' \
  -H "Authorization: Bearer $CRON_SECRET" \
  https://hub.connectingclimateminds.org/api/cron/retention
02

Mint Cloudflare Turnstile keys

You Anonymous comments dead

The server has always verified Turnstile tokens and fails closed, so with no keys every anonymous comment is refused with “Anonymous commenting is currently unavailable. Please sign in.” The widget is now built and wired — it just needs a site key to render.

  1. Cloudflare dashboard → Turnstile → Add widget.
  2. Add every hostname that will show the widget: hub.connectingclimateminds.org, your Vercel preview domain, and localhost for development.
  3. Widget mode Managed is the right default.
  4. Copy Site Key → NEXT_PUBLIC_TURNSTILE_SITE_KEY, Secret Key → TURNSTILE_SECRET_KEY. Set both in Vercel (all scopes) and in .env.local.
  5. Redeploy — the site key is a NEXT_PUBLIC_ value baked at build time.
Verify Sign out, open any case study, scroll to the comments. The Turnstile checkbox renders and the Post button stays disabled until it passes.

No code or CSP change needed — challenges.cloudflare.com is already allow-listed in script-src and frame-src.

03

Rotate the Algolia search-only key

You All search returns nothing

The public search key currently 403s on every index, so content search, people search, and the command palette all come back empty. The admin key and the indices themselves are fine — the wiring is correct, the key is simply revoked.

  1. Algolia dashboard → your app → Settings → API Keys.
  2. Copy the Search-Only API Key, or create a new key restricted to the four live indices: case_studies, news, agendas, users.
  3. Set NEXT_PUBLIC_ALGOLIA_SEARCH_API_KEY in Vercel (all scopes) and .env.local. Confirm NEXT_PUBLIC_ALGOLIA_APP_ID and the server-only ALGOLIA_API_KEY (admin) are also present.
  4. Redeploy.
Verify /en/search?q=climate returns grouped results under Content, People and Regions.
04

Decide the engagement flag

Decision Reversible

The entire workspace, messaging and notification area is invisible in production today. NEXT_PUBLIC_FEATURE_ENGAGEMENT is the only live feature flag and it defaults to off, so a forgotten variable can never leak unfinished UI. It is already true on Preview.

  • Flipping it on Production reveals: the sidebar Workspaces entry, Messages and Notifications in the user menu, the header notification bell, the “Start a workspace” CTA, and the /collaborations, /messages, /collaborate/events and /moderation/broadcast routes.
  • It gates UI only — the database models, API routes and services ship either way.
  • Because it is a NEXT_PUBLIC_ value it is baked at build time: changing it requires a redeploy, not just an env edit.
Sequence this last. Turn the flag on only after tasks 1, 5 and 6 are done — workspaces without R2 CORS can't accept uploads, and notifications without a verified Resend domain email nobody.

External services

Cloudflare · Resend · Sanity
05

Add a CORS policy to the ccm-collab bucket

You Uploads fail in-browser

Workspace file uploads fail with “Failed to fetch” at the browser PUT. It reads like an application bug but it is a CORS preflight rejection — the server-side presign works fine, the browser is simply not allowed to talk to the bucket. This has been on the setup list since June and is the single reason the Files tab looks broken.

  1. Cloudflare dashboard → R2 → ccm-collab → Settings → CORS Policy.
  2. Paste the policy below, replacing the preview host with your actual Vercel preview domain.
[
  {
    "AllowedOrigins": [
      "https://hub.connectingclimateminds.org",
      "https://connecting-climate-minds.vercel.app",
      "http://localhost:3000"
    ],
    "AllowedMethods": ["PUT", "GET", "HEAD"],
    "AllowedHeaders": ["content-type"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
Verify Open a workspace → Files → drag a PDF onto the dropzone. It uploads, then appears in the list with an Open PDF action.
06

Verify a sending domain in Resend

You Mail reaches one inbox

The Resend account has no verified domain, so outbound email only reaches the account owner — every other recipient 403s. Case-study status emails, reply and mention notifications, the weekly digest and issue reports have all been failing silently for everyone else.

  1. resend.com/domains → Add Domain.
  2. Add the DNS records Resend gives you (SPF, DKIM, and a DMARC record) at your registrar. Wait for the status to read Verified.
  3. Point the three from/to variables at that domain in Vercel: CASE_STUDY_EMAIL_FROM, ISSUE_REPORT_EMAIL_FROM, and ISSUE_REPORT_EMAIL_TO (currently pinned to a personal address as a workaround).
Verify Submit the in-hub “Report a problem” widget as an editor, or approve a case study in Studio, and confirm the mail lands somewhere other than the account owner's inbox.

Notification emails already carry RFC 8058 one-click unsubscribe headers, so deliverability should be good once the domain authenticates.

07

Make the production_2 dataset private

You Live data exposure

The Sanity dataset is world-readable, so non-approved case studies and reviewer notes can be read anonymously through the API even though the application filters them out of every page. The app-layer filtering is correct; the datastore is simply open.

  1. Before flipping: confirm SANITY_API_READ_TOKEN is set in all Vercel scopes. A private dataset means every read needs a token — the server client already sends one, but an unset token turns every content page into an error.
  2. Test on Preview first: point a preview deployment at a private dataset and load the homepage, a case study, the atlas, and Studio.
  3. sanity.io/manage → project → Datasets → production_2 → set visibility to Private.
  4. Redeploy production and smoke-test content pages immediately.
Rollback is instant. If content pages break, set the dataset back to public while you fix the token wiring — the exposure returns, but the site stays up.

Security decision

Needs a judgement call before it needs work
08

Decide what to do about supabase-users.json

692 people Decision first

A 1.3 MB Supabase export containing 692 email addresses, 692 password hashes, and full profile PII (names, organisations, locations, sign-in timestamps) was committed in e8cf1bb20. It is untracked as of this work, but it remains in git history — reachable from master and five other branches, 557 commits back, and pushed to GitHub.

What the risk actually is

  • These are legacy Supabase credentials. The Hub authenticates through Clerk now, so the hashes grant no access to this application.
  • The real exposures are credential stuffing (people reuse passwords elsewhere) and the PII itself — which is a GDPR matter regardless of whether the passwords are usable.
  • Severity therefore hinges on one question: is the repository private, and who has had access to it? If it has always been private and access is limited to you and known collaborators, this is a cleanup. If it was ever public, it is an incident with a notification duty.

If you purge the history

  1. Coordinate first — this rewrites every commit SHA after e8cf1bb20 on all branches. Everyone must stop pushing, and open pull requests will need to be recreated.
  2. Run the rewrite on a fresh mirror clone, then force-push all branches and tags.
  3. Everyone re-clones. Nobody merges from an old clone — that single act puts the blob straight back.
  4. Ask GitHub Support to purge cached views, and check whether any forks exist. Until they do, the blob stays reachable by SHA through the API.
# from a scratch directory, never your working clone
brew install git-filter-repo
git clone --mirror https://github.com/noodleman1991/CCM_GOH ccm-purge.git
cd ccm-purge.git
git filter-repo --path supabase-users.json --invert-paths
git push --force --all
git push --force --tags
The alternative is legitimate. If a rewrite is too disruptive, the defensible path is: confirm the repo is private, tighten access, decide on user notification with counsel, and leave history alone. What is not defensible is leaving it undecided.

Where the workspace stands

Collaboration workspaces are feature-complete for a first release: eight surfaces, a four-role permission model, and a public read-only mode. The honest caveats are in what's pending — one of them (concurrent PDF annotation) can lose a person's work, so read that before inviting a big team in.

A full audit of this area while writing this brief turned up a cross-workspace permission hole — authorization checked the workspace you claimed, not the workspace the task or document actually lived in. That is now fixed and covered by tests, along with three rendering defects. The list below is what remains.

Part two, continued

What's pending

Ordered by what a user would notice first. None of these block a launch; the first one should shape how you introduce the feature to a team.

✓
Fixed while writing thisDone

A cross-workspace permission hole (any editor could rename, delete or reassign content in another workspace whose ids they knew), tasks assignable to non-members, the attention strip printing raw database enums and JSON, public output links going to the wrong page, and two translation keys that rendered as raw key paths. Four commits, eight new tests.

01
Concurrent PDF annotation overwritesCan lose work

Annotations are stored as one shared blob per file, saved by exporting the whole document a second after any change. If two people annotate the same PDF at the same time, the second save silently replaces the first person's notes — no conflict, no warning. The fix is per-annotation rows rather than a single JSON document. Until then, treat PDF notes as a one-reader-at-a-time activity.

02
Nothing updates liveBy design, for now

There are no websockets: notifications poll every sixty seconds and everything else refreshes on navigation. A teammate's new comment, task or file appears when you reload, not as it happens. This was a deliberate v1 decision to avoid running socket infrastructure, and it is the main thing that will make the workspace feel less alive than Notion or Linear.

03
You can't tell who wrote which note

The annotation record keeps only the last person to save. In a shared reading session you see the notes but not their authors — and the “updated by” name will often be someone who merely moved a highlight. Same root cause as item 01; the same fix resolves both.

04
Workspaces don't appear in search

Four indices are live — case studies, news, agendas, people — but collaborations were never added. A public workspace can only be found by following a link or the collaborate listing, never by searching its name. Indexing was scoped in the original plan and deferred.

05
Ownership transfer is a two-step manoeuvre

There is no “transfer ownership” button. An owner promotes someone else to owner in the Members tab and then leaves — and a sole owner cannot leave at all until they do. Account deletion handles this automatically (it promotes the longest-standing member, or archives), but the deliberate path is unobvious.

06
Staff can enter but barely act

Editors and admins reach any workspace shell, but arrive with no membership role — so they see a read-only view whose only staff power is Archive. The collab:moderate capability exists in the permission model with no interface behind it. Fine while the community is small; thin if you need to act on a report.

07
No file versions or access log

Re-uploading a document adds a second file rather than a new version of the first, and there is no record of who downloaded what. Separately: if you configure a public bucket hostname, files in public workspaces are served from permanent unguessable URLs rather than expiring signed ones — a deliberate trade for shareability, worth knowing before someone puts something sensitive in a public workspace.

08
Unvalidated on a real phoneVerification gap

This is the weakest area against the project's mobile-first standard. The shell header packs title, visibility badge, toggle, public-page link, Leave and Archive into a single non-wrapping row; thread and file rows do the same. There are almost no responsive utilities in these components — only the tab strip scrolls deliberately. Expect horizontal overflow on a phone until this gets a pass.

09
Notifications aren't clickable

The feed renders no links. “You were assigned a task” arrives with no way to reach the task — and because the workspace tab lives in component state rather than the URL, there is no address to link to anyway. Fixing the second makes the first possible, and would also give threads and tasks shareable links.

10
The project channel has no button

A workspace-wide message channel is implemented and unit-tested, but nothing in the interface calls it, so it can never be created. Members who join after a channel exists are also never added to it. Either wire up “Message team” or drop the feature — right now it is documented capability that users cannot reach.

11
Archive is one-way, and doesn't lock anything

There is no unarchive, and the permission model never checks status — an archived workspace disappears from listings while remaining fully editable by its members. An accidental archive currently needs a database write to undo.

12
English leaks through the server layer

The interface is translated into four languages, but the activity feed templates, the output type labels, the starter content in every new workspace, and every server-side error toast are hardcoded English. A French member gets a French interface and an English workspace.

13
Output status refreshes on every page view

Each workspace load makes a Sanity round-trip and may write back status changes and fan out notifications — from a read path. Two members opening the page at the same moment after a review can both detect the change and send duplicate “output approved” notifications, and a slow Sanity makes every workspace slow. This belongs on the webhook that already exists, not on page load.
