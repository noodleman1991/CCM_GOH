**Architecture (grounded in the codebase):**
- The homepage is already a `blocks[]` page-builder (Slice H1). Blocks render through `components/blocks/index.tsx` (`<Blocks>`), which spreads only the GROQ block projection onto each component + `locale`/`isRTL`/`userId`. It does **not** fetch per-block data. So a block that needs server data (like the events-calendar in H3) is an **async server component that fetches, then renders a client child** (the H3 pattern: `components/blocks/events/events-calendar.tsx` → `events-calendar-client.tsx`).
- **Gap discovered:** the current `lived-experiences-carousel` component (`components/blocks/carousel/lived-experiences-carousel.tsx`) is a **client** component that takes `experiences` as a prop (default `[]`). When placed in `blocks[]`, `<Blocks>` never injects `experiences`, so it would render its empty state. H4.1 fixes this by adding a **server wrapper** that fetches experiences (via the existing `livedExperiencesCarouselQuery`, filtered by `filterBy`/`maxItems`/`featured`) and renders the existing client carousel with the data + the "View all" link. This mirrors the H3 events-calendar server→client split exactly.
- The §4.1 target order (from `docs/superpowers/specs/2026-06-26-homepage-redesign-design.md` "Target §4.1 home, section → block"):
  1. `hero-1` — Hero (Explore/Collaborate CTAs + blob). **Already authored on `blocks[0]` by `scripts/set-hero-ctas.mjs`. PRESERVE verbatim.**
  2. `region-map` — Explore by region.

  4. `events-calendar` — Events (H3, already built/registered).

  6. `cta-1` — Share your lived experience (submit banner, H4.3).
  7. `logo-cloud-1` — Funder / partner strip.

  ```tsx
  import { getTranslations } from "next-intl/server";
  import { stegaClean } from "next-sanity";
  import { client } from "@/sanity/lib/client";
  import { livedExperiencesCarouselQuery } from "@/sanity/queries/carousel/lived-experiences-carousel";
  import LivedExperiencesCarousel from "./lived-experiences-carousel";

  type Props = {
    _type?: "lived-experiences-carousel";
    title?: string; subtitle?: string;
    background?: any; padding?: any;
    filterBy?: { communities?: Array<{ _ref: string }>; tags?: Array<{ _ref: string }>; authors?: Array<{ _ref: string }> };
    maxItems?: number; featured?: boolean;
    viewAllLink?: boolean;
    locale?: string;
  };

  export default async function LivedExperiencesCarouselServer({
    filterBy, maxItems = 10, featured = false, viewAllLink = true, locale = "en", ...rest
  }: Props) {
    const communities = filterBy?.communities?.map((c) => c._ref) ?? null;
    const tags = filterBy?.tags?.map((t) => t._ref) ?? null;
    const authors = filterBy?.authors?.map((a) => a._ref) ?? null;
    const experiences = await client.fetch(livedExperiencesCarouselQuery, {
      communities: communities?.length ? communities : null,
      tags: tags?.length ? tags : null,
      authors: authors?.length ? authors : null,
      featured: !!featured,
      maxItems,
    });
    let viewAllLabel: string | undefined;
    if (stegaClean(viewAllLink) !== false) {
      const t = await getTranslations({ locale: locale as "en"|"es"|"fr"|"ar", namespace: "livedExperiences" });
      viewAllLabel = t("viewAll");
    }
    return (
      <LivedExperiencesCarousel
        {...rest}
        experiences={experiences || []}
        maxItems={maxItems}
        featured={featured}
        locale={locale}
        viewAllHref={viewAllLabel ? "/lived-experiences" : undefined}
        viewAllLabel={viewAllLabel}
      />
    );
  }
  ```
  > Verify `livedExperiencesCarouselQuery` accepts these param names (it uses `$communities`/`$tags`/`$authors`/`$featured`/`$maxItems` — confirmed in the query file). Verify the `livedExperiences` namespace has (or add) a `viewAll` key.
